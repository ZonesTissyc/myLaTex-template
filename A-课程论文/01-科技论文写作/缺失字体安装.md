一、先检查需求与现有字体
1. 识别 Linux 发行版或 macOS 版本、CPU 架构、实际登录用户、权限和当前 LaTeX 引擎。阅读工作区中适用的 AGENTS.md、README、模板说明、tex/cls/sty 文件、latexmkrc 和已有日志；重点检查 fontspec、ctex、setmainfont、setsansfont、setmonofont、setCJKmainfont 及相关字体配置。
2. 列出“模板要求的字体家族与字形 → 已安装的真实家族和文件路径 → 缺失项”。特别核对 Times New Roman、Arial、Courier New、Consolas、宋体 SimSun、黑体 SimHei、楷体 KaiTi、仿宋 FangSong，以及模板指定的粗体和斜体；不要看到这些示例便全部安装。
3. Linux 可用 fc-list、fc-match 和 fc-scan 检查家族、样式与 TTC 字体集合。fc-match 总会尝试返回最接近的字体，不能因为命令成功或有输出，就认定指定字体已安装；必须比对返回的家族和文件。macOS 结合 system_profiler SPFontsDataType、字体目录和实际引擎检查，不能仅因没有 fc-list 就判断未安装字体。
4. 已满足要求的字体直接复用；文件名不等于内部字体家族名。确认是缺字体，而不是 TeX 宏包缺失、引擎选错、字体名拼写错误或缓存问题。遇到缺少 LaTeX 引擎时，先报告并转到环境安装流程，不继续声称能完成编译验证。

二、优先核实软件包和授权来源
1. 先搜索当前发行版的软件仓库、软件包说明和微软/Apple 官方资料，核实准确包名、适用系统、实际字体清单、来源及许可。不要编造包名、添加不明第三方仓库，或把网上的“微软全字体包”一律视为官方授权。
2. Debian / Ubuntu：先检查 apt-cache policy ttf-mscorefonts-installer 和包说明。Debian 通常位于 contrib，Ubuntu 通常位于 multiverse；仓库未启用或无候选版本时，说明原因并征求确认，不擅自修改软件源。确认权限、空间和许可后，才执行 apt-get update 和所需包的安装；先评估依赖变更，不做全系统升级。
3. ttf-mscorefonts-installer 提供 Times New Roman、Arial、Courier New 等传统微软核心字体，但不包含 SimSun、SimHei、KaiTi、FangSong、Consolas、Calibri 或 Cambria，不能拿它当作完整 Windows 字体库。该包还可能需要联网下载，apt 显示已安装并不证明字体下载成功，安装后必须再次核对。
4. 如遇许可确认，先展示条款并让我确认。只有我明确接受后，才按该发行版当前文档配置 debconf 或非交互安装；不能用 DEBIAN_FRONTEND=noninteractive 等设置代替用户同意。其他 Linux 发行版也先核实本地包管理器及可信来源，不能照搬 apt 命令。
5. macOS 不使用 apt。先检查系统已有字体和合法安装的 Microsoft Office 等软件提供的字体；如需通过 Homebrew 或其他包管理器补充，先查证当前真实存在的软件包及来源、许可，不臆造微软字体 cask，不为装字体而顺带安装 Office、Wine 或无关大型软件。
6. fonts-liberation、fonts-crosextra-carlito、fonts-crosextra-caladea、Noto CJK 等是开源替代字体，不等于微软原字体。模板要求精确字体时不能静默替换、伪造别名或改写模板；仅在我确认接受版面差异后，另行采用替代方案。

三、软件包不能满足时，从 AList 按需补齐
1. 先报告仍缺少的字体、计划使用的压缩包、安装范围和目录。微软 Windows 自带字体通常不允许任意复制到其他电脑或服务器；共享链接可下载不代表获得使用或再分发许可。先核实相应许可或让我确认有适用于目标系统的授权；无法确认时，暂停这些字体的安装，给出合法来源或开源替代方案，不把字体加入 Git 或重新公开分发。
2. 在本次专用临时目录下载。先检查目标目录、下载缓存和临时目录的可用空间与写入权限，结合实际包大小、解压清单和安装副本预留空间，不只检查 ZIP 的大小。不要整库下载安装，只获取包含缺失字体的必要压缩包。
3. 请求具体文件链接并检查 HTTP 状态、跳转后的地址、Content-Disposition 和文件内容。GET 可使用 curl --fail --location --show-error，并设置合理的超时和有限重试；HEAD 不受支持时，使用受限的 Range GET，若服务器忽略 Range，则及时停止探测，避免意外下载大文件。拒绝 HTTPS 降级或关闭证书校验。不能把返回 200 的登录页、错误 HTML 或 JSON 当成字体 ZIP。
4. 下载保存到明确的临时文件名，完成后验证 ZIP 文件头和压缩包完整性。如果来源提供可信校验值则比对；仅自行计算 SHA256 只能记录本次文件，不能据此宣称来源可信。共享需要密码、链接失效、下载中断或校验失败时，停止并报告，不猜测文件名或绕过访问控制。
5. 解压前先列出条目、展开大小和字体文件名，拒绝绝对路径、.. 路径穿越、越界符号链接及异常解压体积。只在独立暂存目录提取所需字体及许可文件，不执行压缩包内的 EXE、脚本或安装器；不要把整个压缩包直接展开进系统字体目录。
6. 仅考虑系统和实际引擎支持的 TTF、OTF、TTC、OTC 等字体文件。扫描字体内部家族、样式和集合索引后，再挑选缺失项；同名不同版本或已有字体冲突时先报告，不覆盖旧文件。Open Sans 仅在模板确实需要时安装，不能用来冒充宋体或微软字体。
7. Windows 包当前清单中的候选文件位于 Windows系统字体/Fonts/ 下，包括 simsun.ttc、simhei.ttf、simkai.ttf、simfang.ttf、times.ttf 和 consola.ttf，以及部分粗斜体文件。这些只是定位线索，执行时仍须重新列出压缩包并核对内部家族、所需样式和实际版本，不仅按文件名判断。

四、按系统安装，默认仅当前用户
1. Linux：优先放入当前用户的 XDG 字体目录（通常为 ~/.local/share/fonts/latex-extra/；如已设置 XDG_DATA_HOME，使用对应目录），确认该目录在 Fontconfig 搜索路径内。只有我明确需要所有用户使用且具备权限时，才安装到 /usr/local/share/fonts/latex-extra/；不要手动覆盖包管理器维护的 /usr/share/fonts。
2. Linux 文件通常使用 0644，目录使用 0755，不设 777。复制后对安装目录运行 fc-cache -f，再用 fc-list、fc-scan 和家族匹配检查真实字体；只为必要操作提权，不改变整个系统字体目录的所有权。
3. macOS：当前用户安装到实际用户的 ~/Library/Fonts/，逐个检查重名与重复字体；全局安装仅在我确认并授权后使用 /Library/Fonts/。不写入 /System/Library/Fonts，不关闭 SIP。尽量通过命令行完成复制和检查，但若字体存在有效性警告或自动验证工具不可用，应如实说明，并请我在“字体册”中验证，不能绕过系统警告。
4. macOS 不照搬 Linux 缓存命令；仅在实际 TeX 环境确实使用 Fontconfig 时刷新相应缓存。LuaLaTeX 如依赖 luaotfload 且确有缓存问题，可核实当前命令后更新该用户字体数据库；不要无差别清空系统缓存、强制重启或删除已有字体。
5. 检查当前编译用户与安装字体的用户是否一致；远程服务器、容器或 CI 中的引擎必须能访问字体目录，不能因为宿主机已安装就宣称容器里也可用。不改写 HOME，不把普通用户字体装到 /root。

五、实际验证并报告
1. 在独立测试目录，用模板要求的真实引擎编译最小文档，逐一加载要求的字体并覆盖所需中文、英文、数字及粗斜体；检查退出码、日志中的 font-not-found、Missing character 等信息和生成的非空 PDF。
2. 再按模板原有方式独立构建，不覆盖模板自带参考 PDF 或用户源码。若有 pdffonts 等检查工具，核对 PDF 中的实际字体和嵌入情况；不能仅凭工具返回成功或“无报错”便宣称外观一致。有参考 PDF 时比较版面，无法查看时如实标注视觉验证未完成。
3. 最后列出原本可用、新安装、仍缺失的字体及真实家族名、来源、版本、安装路径、缓存操作和编译结果。保留本次安装文件清单，方便日后仅撤销新增文件，不删除或替换原有字体。
